AI session context on every pull request (GitHub) and merge request (GitLab). When audit findings exist, contradictions are surfaced inline for reviewers.

## GitHub

SessionFS has a GitHub App that automatically comments on PRs with AI session context.

### Setup

1. Dashboard → Settings → Integrations → GitHub Integration → **Connect GitHub**
2. Install the SessionFS GitHub App, select the repositories you want to monitor, and sign in to GitHub when asked. SessionFS links the installation only after GitHub confirms your GitHub account can access it (for an organization install, sign in as an organization admin).
3. Push sessions from those repos: `sfs push ses_xxx`

If the app is already installed, use **Link existing installation**. Installations linked before ownership checks existed show **Verify ownership with GitHub**; PR comments keep working, but repository verification needs the re-check.

When a PR is opened on a branch that has matching sessions, SessionFS posts a comment with:
- Session title and tool info
- Message count and model used
- Contradictions table (if audited)
- Link to full session in the dashboard

### Configure in dashboard

Dashboard → Settings → Integrations → GitHub Integration

Options:
- Auto-comment on PRs (on/off)
- Include trust scores (on/off)
- Include session links (on/off)

## GitLab

SessionFS supports GitLab merge request comments for both cloud and self-hosted instances.

### Setup

1. Create a GitLab personal or project access token with `api` scope
2. Add a webhook to your GitLab project:
   - URL: `https://your-sessionfs-domain/webhooks/gitlab`
   - Secret token: a secret you choose — enter the same value in SessionFS in step 3 (self-hosted operators can instead set one server-wide secret with `SFS_GITLAB_WEBHOOK_SECRET`)
   - Events: "Merge request events"
3. In the dashboard, open **Settings → Integrations → GitLab**, enter your instance URL, access token and webhook secret, and click **Connect GitLab**. Stored secrets are never shown again. **Disconnect** removes them.

   To script this instead, call `PUT /api/v1/settings/gitlab` (body: `instance_url`, `access_token`, optional `webhook_secret`); `DELETE /api/v1/settings/gitlab` disconnects. If you omit `webhook_secret` when first connecting, SessionFS generates one and returns it once in that `PUT` response so you can copy it into GitLab; omitting it on a later update keeps the current secret. `GET /api/v1/settings/gitlab` never returns the secret — only whether one is set (`has_webhook_secret`).

### Self-hosted GitLab

Works with any GitLab instance — set the instance URL to your instance in Settings → Integrations → GitLab (or `instance_url` in the API).

### AI Context (via SessionFS)

| Session | Tool | Messages | Trust |
|---------|------|----------|-------|
| Debug auth middleware | Claude Code | 47 | 74% |

**2 contradictions found:**

| Severity | Claim | Reality |
|----------|-------|---------|
| CRITICAL | "Test passes" (msg #34) | Exit code 1 |
| HIGH | "Created validator.py" | No Write call |
