title: "Web Dashboard"
---

The SessionFS dashboard is a management interface for browsing sessions, organizing projects, handling team handoffs, and configuring sync. It is not a chat UI — you interact with your AI tools natively and use the dashboard to review, resume, and share the resulting sessions.

## Accessing the Dashboard

The hosted dashboard is at [app.sessionfs.dev](https://app.sessionfs.dev). Self-hosted deployments serve the dashboard from their own domain (see [Self-Hosted](/docs/self-hosted)).

Log in with your API key. You can generate one with `sfs auth login` or from the Settings page if you already have an account. After login, the dashboard remembers your session until you explicitly log out.

---

## Sessions

The home page (`/`) lists all synced sessions grouped by date. Each card shows the tool badge, title or first message, model, message count, token usage, and relative timestamp.

### Resume Hero

At the top of the list, the most recent session from each tool is highlighted with a one-click resume command you can copy to your terminal. This is the fastest way to pick up where you left off.

### Lineage Grouping

Forked and resumed sessions are grouped under their root session. Expanding a lineage group shows the full chain of parent and child sessions so you can trace how a conversation evolved.

### Filters and Sorting

- **Tool filter** — narrow to a single tool: Claude Code, Codex, Gemini CLI, Copilot, Cursor, Amp, Cline, Roo Code, Kilo Code, or Antigravity.
- **Model filter** — narrow to one or more models, populated from your sessions with counts. Model ids that carry a trailing date stamp (like `gpt-5-20250127`) show a friendlier name (the date is stripped for display only; filtering uses the raw id, and screen readers hear the raw id). Sessions with no recorded model appear as **Unknown model**. The selection lives in the page URL, so it survives a refresh or a shared link; a selected model that isn't in the current list (another tool filter, or a shared link) still shows with a 0 count so you can untick it, and **Clear models** resets the filter. Sorting by model is done on the server, across every page.
- **Date range** — Last 24 hours, 7 days, 30 days, or all time.
- **Sort** — by date, tool, model, message count, token count, or title.

### Bulk Select and Find Duplicates

Check the box on multiple sessions to delete them in bulk. The **Find Duplicates** button scans for sessions with identical content (common when the same session is imported by multiple watchers) and lets you remove extras.

### Bookmarks and Folders

The left sidebar shows bookmark folders. Drag a session onto a folder or use the bookmark button on any session card to organize your work. Folders are user-level — they do not affect the underlying `.sfs` data.

## Session Detail

Click a session to open its detail view (`/sessions/:id`). The header shows the tool, model, alias, cost estimate, and token counts.

### Messages Tab

The default tab displays the full captured conversation as a readable transcript with paginated messages (50 per page). Tool calls and tool results are rendered with tool-aware formatting — file edits, command runs, and search results show as structured blocks rather than raw JSON. Use the order toggle to switch between oldest-first and newest-first. Sidechain and empty messages can be filtered out for readability. Click a page number or use the jump control to navigate long sessions.

### Changes Tab

Lists every file the agent created, edited or deleted in the session, with line counts and a diff per file (v0.23.0). It is rebuilt from the edit, write and patch tool calls captured for Claude Code, Codex, Cursor, Gemini CLI, Cline, Roo Code, Kilo Code, Amp, Copilot CLI and Antigravity. Diffs come from the stored, already-redacted session, so a redacted secret never reappears. A session that only read files shows no changes. API: `GET /api/v1/sessions/{id}/changes`.

### Summary Tab

Shows the deterministic summary (key decisions, files touched, commands run) and, if available, the narrative LLM summary generated during sync.

### Audit Tab

Displays the LLM Judge trust score (0--100), individual findings with CWE mapping and confidence levels, and linked evidence from the conversation. Each finding can be dismissed or confirmed. Use the **Export** button to download the audit report as JSON.

### Actions

- **Ask the helper** — opens the [session helper](/session-helper/) scoped to this session (Enterprise).
- **Resume** — copies the `sfs resume` command for this session to your clipboard.
- **Handoff** — opens the handoff modal to send the session to a teammate.
- **Share** — creates a public share link. The recipient sees the session as a read-only page at `/s/{token}` — no account required. Links are owner-revocable, can be password-protected, are never cached or search-indexed, and are hard-gated by a DLP scan of exactly the content served (tool inputs included), re-run whenever the underlying session changes.
- **Alias** — click the alias field to set a short memorable name (e.g., `auth-refactor`). Aliases are unique per user and can be used in place of session IDs in the CLI.
- **Bookmark** — add the session to a folder from the more menu.

## Search

Press **Cmd+K** (or Ctrl+K) from any page to open the command palette. Type to search sessions by title, alias, or message content. Arrow keys navigate results; Enter opens the selected session; Escape closes the palette.

The full search page (`/search`) adds tool and date-range filters on top of the text query. Results show matching snippets with the search term highlighted.

## Projects

The Projects page (`/projects`) lists all project contexts linked to your repositories. Each card shows the project name (or normalized git remote), session count, and a preview of the context document. Project pages are addressed by project id (`/projects/proj_...`); older links by git remote redirect there, and a merged project's link opens the project it was merged into.

### Creating a Project

Click **New Project** to create one. Provide a name and optionally link a git remote. The project is the container for shared context, knowledge entries, and wiki pages.

### Project Detail

A project is organized into five sections. The current section and sub-tab are kept in the address bar, so you can link straight to them and the back button works.

- **Overview** — when the context was last compiled and how many claims are waiting, with a one-click compile when it is out of date, then the project's compiled context document, shown as a readable document (lists, quotes, tables, task lists and code blocks render properly) with an **On this page** list of its sections beside the text that highlights the one you're reading; on a phone the list is a collapsible menu above the text. Click **Edit** to change it in the markdown editor. This document is injected into sessions via MCP or `--append-system-prompt-file`.
- **Knowledge** — **Entries** (structured facts captured with `add_knowledge`, with type, text, confidence and creation date), **Pages** (wiki pages with backlinks, including compiled section pages) and **History** (past compilations).
- **Work** — **Tickets**, **Agent runs** and **Personas** for the project's agent team. Opening a ticket shows its status, assignee, Jira issue and actions first, then the description and acceptance criteria, with dependencies and child tasks folded away. Below that, one **Activity** timeline merges comments, trusted review verdicts (marked with their round), Jira sync events and edits in time order, and ends with the comment box. On a ticket, **Promote to Jira** opens an editable Jira preview, and **Link existing issue** attaches the ticket to an issue already in Jira (Enterprise). The assignee picker lists personas and teammates: a teammate assigned directly gets a "Your turn" notification, and the picker warns when the chosen persona represents nobody, so no one would be notified. **Assigned to me** filters the list to your tickets. On an agent run, **Replay** queues a copy with an edited prompt or context, and **Compare** shows which findings were added, removed or unchanged between two runs. Clicking an org persona opens its recent activity.
- **Rules & Skills** — **Rules** (canonical project rules compiled into each tool's instruction file) and **Skills** (the project's installed skills and pending install requests from the marketplace).
- **Settings** — grouped into **General** (rename the project), **Knowledge** (the narrative summary toggle and the **Scheduled KB compile**: nightly, weekly or off, with an optional pending-claims threshold), **Repositories** (linked repos, and merging another project into this one), **Access & ownership** (the project groups that include it, and transferring it) and **Danger zone** (deleting it).

## Handoffs

The Handoffs page (`/handoffs`) has two tabs: **Inbox** (handoffs sent to you) and **Sent** (handoffs you created).

### Claim Flow

When you receive a handoff, its status is **pending**. Click it to see the session context card — a summary of the session being handed off, including tool, model, message count, and the sender's note. Click **Claim** to accept. The session is copied to your account and the status moves to **claimed**. Unclaimed handoffs expire after the configured TTL.

### Status Stepper

Each handoff shows a three-step progress indicator: **Created**, **Claimed**, **Completed**. This makes it easy to see at a glance where things stand across your team.

## Settings

Account settings live at `/settings`, split into sections that each have their own address (for example `/settings/sync`). On a phone the section list becomes a menu.

- **Account** (`/settings/account`) — your account and plan, last sync, and the **Capture Health** card. If a tool ships a format change that silently breaks capture, the daemon detects it (an idle tool is never flagged) and the card surfaces it here — the same signal reported by `sfs doctor`.
- **Preferences** (`/settings/preferences`) — appearance, including light or dark theme.
- **Integrations** (`/settings/integrations`) — your server URL and API key, the **GitHub Integration** for PR-linked sessions and PR comments, and the **GitLab Integration** for merge request comments on gitlab.com or a self-managed instance (connect, update or disconnect; the access token and webhook secret are write-only and never shown back). See [Git Integration](/git-integration/).
- **Data protection** (`/settings/data-protection`) — automatic audit on sync (LLM Judge) and your DLP secret-scanning policy.
- **Sync** (`/settings/sync`) — autosync mode: `off` (local only), `all` (sync every session), or `selective` (sync only sessions on your watchlist).

## Billing

The Billing page (`/settings/billing`) shows your current tier and usage.

- **Tier display** — shows your plan (Free, Starter, Pro, Team, Enterprise, or Admin) and the features included.
- **Upgrade** — select a higher SessionFS Cloud tier.
- **Manage subscription** — opens the subscription page where you can update payment methods, view invoices, or cancel.
- **Organization billing** — if you belong to an org, billing is managed at the org level. The effective tier is resolved from the org, not your individual account.

---

## Organization

The Organization page (`/settings/organization`) has these tabs: **Members** (members, roles and invites), **Personas** (org-wide agent personas, each with an activity panel), **Policies** (organization defaults, the weekly digest opt-out under **Notifications** and, on Enterprise, the session helper AI key), **Integrations** (Jira Cloud and Confluence Cloud, Enterprise: one summary row each, with **Manage** opening that integration's settings) and, for admins, **Security** (single sign-on). Members inherit the org tier for all sync and feature limits.

---

## Admin

The Admin page (`/admin`) is only visible to users with the **admin** tier.

- **User Management** — view all users, their tiers, last activity, and client versions. Adjust tiers or disable accounts.
- **Activity Log** — chronological feed of key events (syncs, handoffs, audits, logins).
- **Licenses** — manage self-hosted license keys, view activation status, and handle grace periods.

## Sidebar and Layout

The left sidebar puts **Sessions**, **Projects** and **Handoffs** first, then groups the rest into **Library** (Marketplace), **Inbox** (Invites, Transfers) and **Manage** (Organization, Billing). The marketplace pages share one sub-navigation. On Enterprise, **Ask the helper** in the sidebar opens the [session helper](/session-helper/) drawer, where answers stream in with links to the sessions they cite and earlier threads are listed under **Conversations**. The session list supports both list and grid layouts — toggle between them to scan many sessions at a glance or focus on detail.

The dashboard works on phones: every page fits a 375 px screen without sideways scrolling, the sidebar becomes a menu, and tab bars scroll instead of overflowing. Tabs follow the standard keyboard pattern (arrow keys, Home, End), and notifications are announced to screen readers.

---

## Light and Dark Mode

The dashboard is dark-first and supports both light and dark themes. It follows your system preference by default. You can override the theme from the layout header or in **Settings → Preferences**.
